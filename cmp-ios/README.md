# cmp-ios

The iOS app-shell — an Xcode project (`iosApp.xcodeproj`), not a Gradle module. It hosts the
Kotlin-exported `ComposeApp` framework assembled by `cmp-shared` and renders it as the app's
entire UI.

## Layout

- **`iosApp/`** — the Swift host: `iOSApp.swift` (`@main` entry, a bare `WindowGroup { ContentView() }`)
  and `ContentView.swift` (a `UIViewControllerRepresentable` wrapping `ViewControllerKt.viewController()`
  — the Compose Multiplatform root exported from `cmp-shared`'s `nativeMain/ViewController.kt`).
- **`Package.swift`** — a SwiftPM binary target exposing the `ComposeApp` XCFramework
  (`cmp-shared/build/XCFrameworks/release/ComposeApp.xcframework`) as a Swift package product. No
  Ruby package-manager toolchain.
- **`scripts/embed-xcframework.sh`** — the `[KMP] Embed and Sign ComposeApp XCFramework` Xcode
  Run-Script build phase. Maps Xcode's flavored `$CONFIGURATION` (e.g. `demoDebug`, `prodRelease`)
  to a Kotlin build type, runs `:cmp-shared:assembleComposeApp{Debug,Release}XCFramework`, and
  stages the SDK-matching `.framework` slice into `FRAMEWORK_SEARCH_PATHS` before Compile Sources.
- **`Configs/*.xcconfig`** — one file per `{flavor}{BuildType}` (`demoDebug`, `demoStaging`,
  `demoRelease`, `prodDebug`, `prodStaging`, `prodRelease`), generated by
  `com.mobilebytelabs.kmp-product-flavors` — do not hand-edit.
- **`Configuration/Config.xcconfig`** — fork identity (`APP_BUNDLE_ID`, `APP_NAME`, `TEAM_ID`),
  regenerated by `./gradlew syncForkConfig` from `app-profile/app.yaml`.

## How it fits

Every Xcode build assembles + embeds the `ComposeApp` framework fresh via the Run-Script phase —
day-to-day builds don't rely on SwiftPM artifact resolution. `Package.swift` exists for forks that
prefer a pure-SwiftPM consumption path.
