# Consuming `core-base/network`

> The transport primitive layer beneath `core/network`. Forks almost never call this module directly
> when adding a new API — that's `core/network`'s `NetworkModule` job (see
> `core/network/CONSUMPTION.md`). This is the lower-level contract: what `NetworkModule` builds atop
> this module, and what's safe to extend here vs. framework-owned.

## Call sequence

1. `core/network`'s `NetworkModule` builds one Ktorfit per declared access point via
   `AccessPointRegistry.ktorfitFor(id)` or the `Module.restApi<T>(id) { it.createXApi() }` DSL — both
   resolve base URL + loggable/proxied host from the registry, which the fork constructs as
   `AccessPointRegistry(AppAccessPoints.points)` (`AppAccessPoints` is generated by `syncForkConfig`
   from `app-profile/app.yaml#network.access_points`).
2. Under the hood, `ktorfitFor` calls `httpClient(setupDefaultHttpClient(baseUrl, loggableHosts,
   proxiedHosts))` — `setupDefaultHttpClient` installs JSON content negotiation, request logging,
   timeouts, an optional `Auth` plugin (`AuthProviders`), and optional certificate pinning via a
   `CertificatePinConfig` (from `core-base/security`).
3. For Supabase access points, `SupabaseClientFactory.clientFor(id)` builds and caches one
   `SupabaseConfigClient` per declared `SUPABASE`-kind `AccessPoint`, reading its publishable key from the generated
   `AccessPoint.supabase` (a BuildKonfig read, never hardcoded); bound in `NetworkBaseModule`. Sign-in
   is not built in: an app that needs it adds kmp-supabase-auth through `SupabaseExtrasProvider`.
4. Responses needing `Result<Success, Error>` wrapping register `ResultSuspendConverterFactory` /
   `ResultFlowConverterFactory` on the `Ktorfit.Builder`.

## Notes

- Safe to extend: `AuthProviders` (basic/digest/bearer + refresh) passed into `setupDefaultHttpClient`;
  `CertificatePinConfig.pins` per-hostname (declared in `core-base/security`, consumed here).
- Framework-owned, don't fork: the per-platform `KtorHttpClient.<platform>.kt` actuals,
  `DynamicBaseUrlPlugin` / `DynamicUrlConfigProvider` (runtime base-URL switching for `AppUrlTypes`).
- Never hardcode a base URL in a fetcher — it always resolves through the `AccessPointRegistry`, so one
  id can back REST or Supabase without call-site changes.

Canonical example: `core/network`'s `NetworkModule` is the shipped consumer — see
`core/network/CONSUMPTION.md` for the feature-facing contract built on top of this module.

Symbols: AccessPointRegistry, restApi, ktorfitFor, setupDefaultHttpClient, SupabaseClientFactory, CertificatePinConfig, ResultSuspendConverterFactory
